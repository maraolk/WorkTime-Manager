# План разработки

## Цель проекта

WorkTime Manager — Angular-приложение для учета рабочих часов по проектам и задачам. Пользователь может запускать таймер, добавлять записи вручную, видеть план/факт по времени и готовить отчет для клиента.

Ценность продукта — убрать разрозненные таблицы и заметки: время, задачи, дневные цели и экспорт отчета находятся в одном интерфейсе с авторизацией и разделением данных между пользователями.

## Пользовательские сценарии

1. Пользователь входит в систему, видит свой текущий день, дневную цель и активный таймер.
2. Пользователь запускает таймер для проекта и задачи, добавляет описание, затем останавливает запись.
3. Пользователь вручную создает, редактирует или удаляет запись времени за выбранную дату.
4. Пользователь фильтрует период, сравнивает плановое и фактическое время, экспортирует отчет в CSV.

## Этапы разработки

| Срок | Задача |
|------|--------|
| До конца апреля | Создать Angular 21 workspace, routing, базовые feature-модули, формы, документацию, mock-сервер |
| Первая половина мая | Реализовать auth flow, protected routes, Signal Store, CRUD записей времени, проекты и задачи |
| Вторая половина мая | Добавить отчеты, фильтрацию, сортировку, экспорт, обработку loading/error состояний |
| До защиты | Покрыть ключевую логику Jest-тестами, добавить Playwright-сценарии, настроить CI/CD и деплой |

## Риски

1. Несовместимость Angular 21 и UI-библиотеки — использовать актуальную Taiga UI 5, не подключать экспериментальные API без необходимости.
2. Большой объем требований для семестрового проекта — сначала закрыть основные сценарии, затем улучшать отчеты и UX.
3. Потеря баллов из-за слабой истории Git — вести работу маленькими коммитами по Conventional Commits.
4. Нестабильность mock API — держать seed-данные в репозитории и описать запуск mock-сервера в README.
5. Недостаточное покрытие тестами — отдельно тестировать store, guards, сервисы отчетов и базовые UI-сценарии.
